# Tricky `main()` Method Rules

> **Module 16 – Command Line Arguments**
>
> **Topic:** Tricky `main()` Method Rules

---

# Introduction

The `main()` method is the entry point of every standalone Java application.

Although its syntax looks simple, there are many rules and exceptions that interviewers frequently ask.

Understanding these rules helps you avoid common mistakes and strengthens your Java fundamentals.

---

# Standard Signature

```java
public static void main(String[] args)
```

This is the signature that the JVM looks for when starting a Java application.

---

# Rule 1 – Parameter Name Can Be Changed

Valid

```java
public static void main(String[] input)
```

```java
public static void main(String[] values)
```

```java
public static void main(String[] abc)
```

✔ The parameter name is **not important**.

The JVM only checks the **type** (`String[]`), not the variable name.

---

# Rule 2 – `String args[]` is Valid

Both are correct.

```java
public static void main(String[] args)
```

```java
public static void main(String args[])
```

The first style is preferred because it clearly associates the brackets with the type.

---

# Rule 3 – `main()` Must Be `public`

Correct

```java
public static void main(String[] args)
```

Incorrect

```java
private static void main(String[] args)
```

```java
protected static void main(String[] args)
```

```java
static void main(String[] args)
```

Reason:

The JVM must be able to access the method from outside the class.

---

# Rule 4 – `main()` Must Be `static`

Correct

```java
public static void main(String[] args)
```

Incorrect

```java
public void main(String[] args)
```

Reason:

The JVM calls `main()` without creating an object.

---

# Rule 5 – Return Type Must Be `void`

Correct

```java
public static void main(String[] args)
```

Incorrect

```java
public static int main(String[] args)
```

```java
public static String main(String[] args)
```

The JVM ignores methods that do not match the required signature.

---

# Rule 6 – `main()` Can Be Overloaded

Valid

```java
public class Demo {

    public static void main(String[] args) {
        System.out.println("Original Main");
        main(10);
    }

    public static void main(int x) {
        System.out.println(x);
    }
}
```

Output

```
Original Main
10
```

The JVM starts execution only from:

```java
public static void main(String[] args)
```

---

# Rule 7 – `main()` Cannot Be Overridden

Static methods belong to the class, not the object.

Therefore, `main()` is **hidden**, not overridden.

---

# Rule 8 – Multiple `main()` Methods Are Allowed

```java
public static void main()
```

```java
public static void main(int a)
```

```java
public static void main(String s)
```

```java
public static void main(String[] args)
```

Only the standard signature is used as the application's entry point.

---

# Rule 9 – Varargs Are Allowed

This is also a valid entry point.

```java
public static void main(String... args)
```

`String...` is compiled as a `String[]`.

---

# Rule 10 – `final` Can Be Added

Valid

```java
public static void main(final String[] args)
```

or

```java
public static void main(final String... args)
```

`final` only prevents reassignment of the local parameter variable.

---

# Rule 11 – Method Modifiers

These are valid.

```java
public static final void main(String[] args)
```

```java
final public static void main(String[] args)
```

```java
public final static void main(String[] args)
```

The order of modifiers does not matter.

---

# Rule 12 – Can `main()` Throw Exceptions?

Yes.

```java
public static void main(String[] args) throws Exception
```

Valid because the JVM allows checked exceptions to propagate.

---

# Rule 13 – Can `main()` Be Synchronized?

Yes.

```java
public static synchronized void main(String[] args)
```

Although valid, it is rarely useful because the JVM invokes `main()` only once per application start.

---

# Rule 14 – Can `main()` Be `final`?

Yes.

```java
public static final void main(String[] args)
```

Valid.

Since `main()` is already `static`, `final` usually provides no practical benefit.

---

# Rule 15 – Can `main()` Be `abstract`?

No.

```java
public abstract void main(String[] args)
```

Invalid.

Abstract methods have no implementation and cannot be `static`.

---

# Rule 16 – Can We Call `main()` Like a Normal Method?

Yes.

```java
public class Demo {

    public static void main(String[] args) {

        System.out.println("First");

        main(new String[]{"Java","Placement"});

    }

}
```

Be careful—calling it recursively without a stopping condition will eventually cause a `StackOverflowError`.

---

# Valid Entry Point Examples

```java
public static void main(String[] args)
```

```java
public static void main(String args[])
```

```java
public static void main(String... args)
```

```java
public static final void main(String[] args)
```

```java
public static void main(String[] args) throws Exception
```

---

# Invalid Examples

```java
private static void main(String[] args)
```

```java
public void main(String[] args)
```

```java
public static int main(String[] args)
```

```java
public abstract static void main(String[] args)
```

```java
public static void Main(String[] args)
```

> Java is case-sensitive. `Main` is **not** the same as `main`.

# Common Interview Questions

### Why is `main()` static?

So the JVM can invoke it without creating an object.

---

### Can `main()` be overloaded?

Yes.

---

### Can `main()` be overridden?

No. Static methods are hidden, not overridden.

---

### Can we use varargs?

Yes.

```java
public static void main(String... args)
```

---

### Can we rename `args`?

Yes.

---

### Can `main()` return an `int`?

No.

The entry-point method must return `void`.

---

# Bootcamp Insight 💡

Many interviewers ask tricky questions about the `main()` method because they test your understanding of **Java syntax**, **method signatures**, **the JVM startup process**, and **static methods**. Focus on *why* each rule exists rather than memorizing the rules.
